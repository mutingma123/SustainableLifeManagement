Model

We consider a team task-allocation problem over a finite planning horizon. A planner must assign
a set of tasks to a set of agents. Let I denote the set of tasks and let J denote the set of agents.
Each task i ∈ I can be assigned to at most one agent j ∈ J. The planner’s decision is therefore not
only whether a task should be carried out, but also which agent should perform it.
When task i is assigned to agent j, it produces a return and consumes workload. We let Rij denote
the expected return generated when agent j performs task i. This return may reflect the value
created by completing the task, such as productivity gains, service value, or project contribution.
We also let Sij denote the random workload required when agent j performs task i. This workload
can represent uncertain time, effort, attention, or cognitive demand. The same task may therefore
lead to different expected returns and different workload realizations depending on the assigned
agent.
Each agent j ∈ J has a limited workload capacity, denoted by Cj . This capacity represents the
maximum amount of work that the agent can reasonably handle during the planning horizon.
Since actual workload is uncertain, a task assignment that looks acceptable in expectation may
still overload an agent in some realizations. For this reason, the planner does not require workload
feasibility in every possible realization. Instead, the planner allows a small probability of overload.
Let α ∈ (0, 1) denote the maximum allowable overload probability for each agent. A smaller value
of α means that the planner is more conservative and places more emphasis on protecting agents
from overload risk.
In addition to controlling overload risk, the planner also wants to avoid highly uneven workload
allocations across agents. A task assignment that places too much work on one agent and too little
on another may increase fatigue, reduce sustainability, and create operational imbalance, even if
the total expected return is high. To capture this idea, the model includes a workload-balance term
in the objective function. Let λ ≥ 0 denote the weight placed on workload imbalance. When λ is
larger, the planner places more importance on balancing workload across agents. When λ = 0, the
planner only maximizes return subject to the chance constraints.

In this formulation, the objective function in (7) maximizes total expected return while penalizing
workload imbalance. The first term measures the total expected value created by the task assignment. The second term penalizes large differences in expected workload utilization across agents.
Constraint (8) ensures that each task is assigned to at most one agent. Constraint (9) imposes
workload feasibility in each scenario unless that scenario is explicitly marked as a violating scenario
through yjω = 1. Constraint (10) limits the total probability of violating scenarios for each agent,
which is the scenario-based implementation of the chance constraint. Constraint (11) defines the
expected workload utilization of each agent, and constraint (12) links these utilization levels to the
imbalance variable Z. Finally, constraints (13)–(16) define the domains of the decision variables.
The planner assigns tasks to agents. Those assignments determine both expected return and
uncertain workload outcomes. The uncertain workload outcomes then determine whether each
agent remains within capacity with sufficiently high probability. At the same time, the assignment
also determines how evenly work is distributed across agents. The optimal solution therefore
balances three forces: return creation, overload-risk control, and workload fairness.

Solution Methodology

The compact formulation in Section 1 can be solved directly by a mixed-integer solver for small and
medium-sized instances. However, when the numbers of tasks, agents, and scenarios become large,
the scenario-based chance constraints become the main computational bottleneck. In particular, the

for each agent-scenario pair. To exploit the structure of the problem more effectively, we solve the
model by a Benders decomposition.
The workload-balance component depends only on expected workload and therefore can remain
in the master problem. By contrast, the scenario-based chance-feasibility condition is naturally
evaluated only after a candidate assignment has been fixed. This structure allows us to separate
the assignment and balancing decisions from the scenario-based feasibility check.

2.4

Algorithmic procedure

The overall solution procedure is iterative. We start with the master problem without any Benders
feasibility cuts. At each iteration, we solve the master problem and obtain a candidate assignment
x̄. We then evaluate the chance-feasibility of x̄ by computing the realized workload in every scenario
and the resulting violation probability for each agent. If the candidate assignment is feasible, then
it is optimal for the original problem. If the candidate assignment is infeasible, then we generate
one or more feasibility cuts of the form (32) or (34), add them to the master problem, and solve
the updated master problem again. The procedure continues until a chance-feasible assignment is
found.
This decomposition is attractive for two reasons. First, it keeps the true objective function and the
workload-balance structure in the master problem, so every master solution is evaluated with respect
to the exact return-balance trade-off. Second, it moves the scenario-based chance-feasibility check
into a separate logical step, which avoids carrying all agent-scenario binary variables explicitly inside
the main optimization model. As a result, the method remains closely aligned with the managerial
logic of the problem: the planner first proposes an assignment, and then checks whether that
assignment is sufficiently safe under workload uncertainty.
